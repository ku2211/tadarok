# تدارك

تتبّع أثر تصحيح مرجعي في مكتبة محتوى عربية، ثم أغلق كل ملاحظة بقرار بشري موثق.

## حالة النسخة

الواجهة والحفظ والمراجعة والتحليل الحقيقي موجودة ضمن النطاق المحدد، والمفتاح مربوط على الخادم. النسخة المعدّلة claims-v10-scoped-fields تمنع الشرح الحر وتقيّد حقول الموضوع المتناقضة، مع الحفاظ على حماية المراجعات وتغير المكتبة. نجح 49 اختبارًا محليًا، إلى جانب اختبارات API وSQLite وفحص TypeScript. هذه اختبارات تشغيل وعقود، وليست قياسًا لدقة النموذج الحي.

قياسات التطوير السابقة تخص النسخة 15: A طابقت 10/10 خلال 4.572 ثانية، وB طابقت 11/12 بالمفتاح الأصلي و12/12 بالمراجَع خلال 5.460 ثانية. حالة B04 غير محسومة الهوية، لذلك يختلف المفتاح المراجَع فيها. كل النصوص طابقت بصماتها والشواهد حرفية، ولم تُعدَّل النتائج بشريًا قبل القياس. راجع [حالة التحقق](docs/VALIDATION-STATUS-2026-10-01.md) و[سجل القياس الكامل](docs/EVALUATION-2026-10-01.md) و[ملخص القياس](evaluation/live-v15-summary.json). العينات متكررة ومن إعداد مساعد البناء؛ لا تمثل دقة عامة أو تقييمًا مستقلًا أو اعتمادًا شرعيًا.

مسار /demo جولة توضيحية بخمس مواد ونتائج ثابتة معلنة. لا تستخدمه دليلًا لدقة الذكاء الاصطناعي أو بديلًا عن منتج مكتمل عند التسليم.

## تجربة الزائر والمراجع

- `/try`: تجربة فعلية بدون حساب. خمس مواد مصطنعة عن تصحيح مرجع حديث، بلا نتائج مسبقة. اضغط فحص الأثر لتشغيل التحليل. لكل جلسة مساحة مستقلة لمدة 24 ساعة وحتى 20 محاولة فحص، ضمن سقف مشترك لجميع الضيوف قدره 100 محاولة خلال 24 ساعة. تظل المراجعة والتصدير متاحة عند بلوغ حد الفحص.
- `/transparency`: المرجع والحدود والخصوصية والخدمات. انتهاء الجلسة لا يعني حذف بياناتها.
- الجلسات القائمة تحتفظ بمحتواها بعد تحديث المثال. افتح نافذة خاصة جديدة لتجربة العينة الجديدة.
- `docs/BASELINE-2026-10-02.md`: توثيق التحضير قبل أيام التحدي. لا تنسبه إلى العمل المنجز خلال 4–6 أكتوبر.

## الاستخدام

1. سجّل الدخول إلى المساحة الخاصة. ارفع حتى 20 ملف TXT بترميز UTF-8، و3000 حرف لكل مادة. هذه النسخة للمواد الاصطناعية أو مجهولة الهوية بالكامل؛ لا ترفع سجلات أو محادثات حقيقية للمستفيدين.
2. أضف النص القديم والتصحيح الذي راجعه المختص واسم المرجع ورابطه وسبب التغيير.
3. شغّل فحص الأثر. إذا تغيرت المكتبة أثناء الفحص فلا يُعتمد كمكتمل وتبقى النتائج السابقة. إذا اختلفت مؤشرات السياق بين القراءتين أو كانت هوية الموضوع مبنية على إعادة صياغة وصفه فقط، تكون الحالة «تحتاج تحققًا». إعادة صياغة الادعاء مع موضوع معلوم تظل ضمن النطاق. قد تزيد هذه السياسة الإحالات البشرية. تتم قراءتان للنصوص بالنموذج نفسه دون مشاركة النتائج بينهما؛ قد تتفقان على خطأ، ولذلك يبقى القرار بشريًا. كل فحص يتضمن طلبين للخدمة ويُسجل مجموع استهلاكهما. GPT-4.1 الكامل أعلى كلفة من mini؛ راقب استهلاك مشروع API. يفحص النموذج نصوص المكتبة المرفوعة فقط. لا يبحث في مواقع خارجية ولا يفتح المرجع. لكل مادة خانة إلزامية يحددها الخادم، ويختار النموذج رقم مقطع ضمن حدودها. يربط الخادم النتيجة بمعرف المادة وينسخ النص الأصلي ويتحقق من وجوده حرفيًا. لا يولّد النموذج شرحًا حرًا؛ يبني الخادم شرحًا محدودًا من الحالة المستخرجة، دون إضافة أسماء أو مواعيد من عند النموذج. صحة الحالة الدلالية نفسها تبقى بحاجة إلى مراجعة.
4. افتح «قراءة المادة كاملة» لفحص سياق الشاهد. يُرفض القرار إذا تغيرت الملاحظة أو المادة أو آخر فحص بعد فتحها. المحرر يعدّل أو يذكر لماذا لا ينطبق التنبيه أو يسجل سؤالًا للمختص. الاعتماد متاح للمراجع ومسؤول المساحة. الدور ليس شهادة تخصص شرعي.
5. أي تعديل لاحق يبطل قرارات المراجعة للنسخة السابقة. يبقى التعديل السابق واسم صاحب القرار محفوظين في السجل.
6. التصدير يخفي هوية الحسابات المنظمة. نصوص المواد والملاحظات لا تخضع لإخفاء هوية آلي مضمون، ولذلك تُراجع قبل مشاركتها.

## التقنية والتشغيل

React مع Vinext على Cloudflare Workers، وD1 للتخزين، وDrizzle لتعريف المخطط، وواجهة Responses API لتحليل دلالي محدود بالسياق. لا يوجد تدريب نموذج ولا قاعدة تراثية ولا فهرس embeddings في هذه النسخة.

- Node 22.13 أو أحدث (الاختبارات التكاملية تستعمل node:sqlite في Node 24).
- ثبّت الاعتماديات عبر pnpm وبالنسخة المحددة في package.json.
- إعدادات الخادم: OPENAI_API_KEY سرّي، OPENAI_MODEL اختياري. الملف .env.example يشرحها، ولا يُنشر ملف .env الحقيقي.
- البناء: pnpm build. يقرأ التطبيق DB من binding Cloudflare. المخطط في db/schema.ts والهجرات المولدة في drizzle، دون إنشاء جداول من طلبات الويب.
- لقاعدة محلية **جديدة وفارغة فقط**، شغّل ملفات SQL الثلاثة بالترتيب بعد البناء. لا يكفي الملف الأول لأنه لا يتضمن كل الجداول الحالية. لا تعِد الأوامر على قاعدة سبق تهيئتها. النشر يدير قاعدة الإنتاج منفصلة.

```bash
set -e
for migration_file in drizzle/*.sql; do
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file "$migration_file"
done
```

- `pnpm start` يشغّل ناتج البناء محليًا. يتطلب تسجيل الدخول المؤسسي بوابة Sites الموثوقة، ولا يعني نجاح البناء إعداد نظام هوية مستقل. تجربة الزائر الإنتاجية تستخدم ملف ارتباط Secure، لذلك يلزم HTTPS في أي استضافة خارجية.

- في بيئة Sites المُدارة يُستخدم المشرف sites-preview، ولا يُغيّر سلوك تسجيل الدخول. الإنتاج يعتمد على ترويسات الهوية التي تضيفها بوابة الاستضافة الموثوقة. لا تعرض Worker خامًا يسمح للزائر بتزوير هذه الترويسات.

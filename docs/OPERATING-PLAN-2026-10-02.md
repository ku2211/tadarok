# تشغيل تدارك وتقدير تكلفة العينة

تاريخ الإعداد: 2 أكتوبر 2026. خطة تشغيل مقترحة مبنية على التنفيذ الحالي، وليست اتفاق خدمة أو تجربة مؤسسة حقيقية.

## نطاق الاستخدام

مكتبة عربية حتى 20 مادة نصية، وبحد 3000 حرف للمادة. يدخل المراجع نص المعلومة السابقة والتصحيح ومرجعه وسبب التغيير. عند طلب الفحص تُقرأ المواد عبر النموذج ثم تظهر مواضع مرشحة للمراجعة. لا يجلب النظام مواقع المصادر، ولا يبحث في مكتبة تراث، ولا يقرر صحة الحكم الشرعي. الإحالة سجل داخل المساحة.

الواجهة React وVinext. التنفيذ Cloudflare Workers والحفظ D1. هوية العضو عبر Sites، والضيف عبر ملف ارتباط آمن لمدة 24 ساعة. الخادم يستخدم Responses API وJSON Schema مع gpt-4.1-2025-04-14 افتراضيًا. تقرأ دعوتان منفصلتان النص نفسه بتركيزين مختلفين، ثم يتحقق الخادم من الشاهد ويشتق التصنيف. لا تعد القراءتان مراجعة علمية مستقلة. الشفرة المرجعية: lib/tadarok/ai.ts وcontract.ts وclaims.ts وguest.ts وapp/api/tadarok/route.ts.

## تكلفة قابلة لإعادة الحساب

في تقرير المستخدم المؤرخ 2026-10-02T00:54:46.100Z، استهلك فحص خمس مواد 11920 رمز إدخال و515 رمز إخراج، وهو مجموع القراءتين. السعر الرسمي الذي راجعه المساعد في 2 أكتوبر 2026: 2 دولار لكل مليون رمز إدخال غير مخزن مؤقتًا، و8 دولارات لكل مليون رمز إخراج.

المصدر: https://developers.openai.com/api/docs/models/gpt-4.1

11920 × 2 / 1000000 + 515 × 8 / 1000000 = 0.02796 دولار.

تقريب العرض: 0.028 دولار لفحص العينة المرصودة. لا نضاعفها لعدد القراءات مرة أخرى. ليست فاتورة فعلية أو تسعيرة ثابتة أو كلفة الحد الأقصى للمكتبة. لا تشمل الاستضافة وقاعدة البيانات والضرائب والعمل البشري، وقد تختلف مع التخزين المؤقت أو السعر أو طول النصوص أو المحاولات الفاشلة. لم تُفحص فواتير الحساب.

## السعة والاستمرارية

- الضيف: حتى 20 محاولة فحص للجلسة، ضمن 100 محاولة مشتركة خلال آخر 24 ساعة. بدء 200 جلسة يوميًا حد منفصل. هذه حدود تشغيل وليست شروط مسابقة.
- بعض الإخفاقات بعد الحجز تستهلك محاولة. لا تصف الحدود بأنها عدد نتائج ناجحة مضمون.
- عند بلوغ الحد تبقى المراجعة والتصدير متاحين. نفاد الميزانية العامة قد يمنع فحص محكّم جديد؛ راجع الاستهلاك قبل العرض ولا تعد بسعة غير محدودة.
- عند فشل الخدمة تظهر رسالة صريحة ولا يحل محلها تحليل مصطنع. تصدير العمل قبل انتهاء الجلسة مسؤولية المستخدم.
- انتهاء وصول الضيف لا يحذف سجلاته من D1. لا توجد آلية حذف ذاتي شامل. لا تستعمل النسخة لسجلات المستفيدين الحقيقية.

## خطة صيانة مقترحة

قبل كل عرض: تحقق من وصول الضيف ورصيد الخدمة وصحة الرابط ومن ملف تصدير بعد الحفظ. أسبوعيًا في التشغيل التجريبي: راجع التنبيهات الخاطئة والإحالات واستهلاك الرموز، وسجل سبب كل تعديل. قبل تغيير النموذج أو القواعد: ثبت مجموعة الاختبار وشغّل المقارنة ثم راجع الحالات التي تغيرت. وسّع الاستخدام بعد تجربة محرر ومراجعة مختص للمحتوى المرجعي. هذه إجراءات مخططة، لا مراقبة آلية مفعلة.

## قياس الفائدة

يحدد مراجع بشري مفتاح العينة قبل التشغيل. تسجل المواضع المتأثرة وغير المتأثرة وغير المحسومة بصورة منفصلة. تقاس دقة التنبيهات والاستدعاء والتنبيه الكاذب ونسبة الإحالة، وزمن الوصول إلى قرار نهائي مقابل مراجعة يدوية على المواد نفسها مع ضبط أثر التذكر وترتيب التجارب. لا توجد حتى الآن دراسة مستقلة أو نسبة توفير وقت يمكن إعلانها.
